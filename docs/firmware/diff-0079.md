# Firmware 2.1.2_0079 compared with 2.1.2_0073

Xiaomi released 2.1.2_0079 in November 2026. The vendor change log is: "Solving the
problem of device protocol handshake failures that occur with extremely low
probability."

The method was static analysis only. Nothing was tested on hardware. Two independent
analyses on different models made the same findings. Addresses use flash base
`0x403000`.

| | 2.1.2_0073 | 2.1.2_0079 |
|---|---|---|
| Raw image | 495,656 bytes | 494,688 bytes |
| MD5 (vendor metadata) | `c62a0cca0422986c4c15056a0e962691` | `7f17cdf1602d92c0eca30178edf1830b` |
| SHA-256 | `65d96d0f6138a36fc62ce62325d055f934dac40d67bc31720f8182ebf5c80ce1` | `7f2ae81cb8ef5eaca9b7da62350be19f8e72de92050e62cfea6d4fa5aa5d5683` |
| Initial stack pointer | `0x20047458` | `0x200474b8` |
| Functions | 1,146 | 1,166 |

Almost all functions moved but did not change: 1,045 have the same code at a new
address, and 67 more differ only in moved addresses, field offsets or register use.
20 functions changed and 16 are new. 86.8 % of the flash bytes are equal after the
address map.

## Change that affects the app: short vendor requests are dropped

The AF07 vendor-request dispatcher reads the length of the write first.

- In 0073 (`0x41fdc4`), it accepts 7 bytes or more (`cmp r0,#7`).
- In 0079 (`0x4203b4`), it accepts 9 bytes or more (`cmp r0,#9`).

The status request `fe dc ba 01 f1 00 01 <sel>` has 8 bytes. On 0079 the charger does
not reply to it. The app now sends a ninth byte, `00`.

- On 0079, the handlers for selectors 1, 2 and 6 do not read byte 8.
- On 0073, these handlers also do not read byte 8. No other code in the dispatcher
  examines the length. Thus the 9-byte request gives the same reply on 0073.
- The 9-byte request that sets the startup artwork (selector 9) is not affected.

The selector table grew from 1–9 to 1–12. Selectors 1–9 use the same handlers. The
new selectors 10, 11 and 12 return data from the port watchdog (see below). The app
does not use them.

## Main change: watchdog for the USB-C port controllers

The changelog item is a new watchdog for the C1/C2 port controllers. It is not a
change to the Bluetooth login. The meaning of the watched fields is inferred.

1. The controller-info read (`0x41512c`, command `0x82`, 16 bytes) gives fields 0, 1
   and 3 to the watchdog (`0x414f84`).
2. If these fields stay the same for more than 300 reads and more than 18 s, the
   firmware stops the port:
   - It sets the port bit in `0x2000ebb4`.
   - It turns off the USB-C output of the port (`0x4163e0`).
   - It increments a counter for that port in the new NV record 5.
3. While the port is stopped, power allocation skips it. Its telemetry shows 0 V,
   0 A and status `0x800`, as for a disabled port.
4. The port starts again when all of these conditions are true:
   - The readings changed for more than 49 reads.
   - At least 10 s went by after the stop.
   - At least 5 s went by after the last attempt.

   Then the firmware writes the power-mode record again (command `0x81`). It reads
   the record back and turns the output on (`0x4163ac`).

The result for the user: a USB-C port whose controller stops responding goes off for at
least 10 s. Then the port comes back. In 0073 the port stayed in the stopped state.

## Other changes

- **Startup artwork.** The holiday startup artwork ("2026" and "Holiday Version") was
  removed. This includes its glyphs, its colour table, its setter path and its branch
  in the logo animation. The NV flag remains, and the app can still read it, but it has
  no visible effect.
- **Version.** The firmware revision changed from `0x73` to `0x79`. Vendor status
  selector 1 returns this value in bytes 6..7.
- **Display configuration.** The `lcd_config_ex` assert (`0x418080` → `0x418680`) does
  not loop forever any more. It calls a hook at `0x1c`. The effect of the hook is
  unknown.

## No change

These items are the same after the address map:

- BLE login state machine: `0x419658` → `0x419c50`.
- FE95 parcel framing check: `0x41eeb4` → `0x41f4b0`.
- OTA/DFU verification, ECDSA, micro-ecc and certificate chain.
- Mijia root public key: byte-identical.
- MIOT property get/set, including the protocol-switch property 2.21 and the
  `07 0f` → `01 0f` remap.
- Layouts of vendor status replies for selectors 1, 2, 6 and 9: same length, offsets
  and sources. See [vendor-status-map.md](vendor-status-map.md).

## App support

The app allows diagnostics, protocol switches and direct installation on 0073 and 0079
(`FirmwareSupport.kt`). The startup-artwork switch is available only on 0073.

## Not checked

- The signed 0079 package (its certificate and signature). The analysis used the raw
  image only.
- 2,529 bytes that look like code but did not disassemble. They were compared as bytes.
- The behaviour on hardware, including how often the watchdog stops a port.
